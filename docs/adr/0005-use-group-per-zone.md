# ADR 0005：用途類組改為逐區劃填寫

日期：2026-10-30
狀態：已採納
相關：`docs/regulations/building-use-groups.md` §6、`docs/regulations/article-79-1-area-exemption.md`

## 脈絡

防火區劃檢討原本以專案資訊的 `建築物用途類組`（規則欄位 `building.use`）代表整棟建築物的使用類組。
使用者指出一棟建築物不一定只有一個用途，要求改成逐區劃設定。

工具讀用途類組的兩條條文都是逐區劃判定：第 83 條第一、二款的Ｈ－２組但書以區劃為單位，第 79 條之 1
講的是「觀眾席部分」「生產線部分」。整棟一個值會讓非 H-2 的區劃拿到放寬，也讓 B-2 建築物裡的 A-1 觀眾席
比不中第一款。

查得三則函釋（2026-10-30 在國土署網站核對內文）：

- 營建署106.02.23營署建管字第1060006313號函、國土管理署113.03.13國署建管字第1130020117號函：建造執照不適用
  《建築物使用類組及變更使用辦法》（附表除外），沒有主從關係，也不必依該辦法第 5～7 條在不同用途間區劃分隔。
- 國土管理署115.05.15國署建管字第1150047679號函：同一空間有多種使用類組者，應同時符合各使用類組之規定。

## 決策

1. **參數放在 Area**：新增 `防火檢討_用途類組`（Area 實體文字參數，GUID `…0017`），規則欄位 `zone.useGroup`。
   區劃本來就是 Area，其他區劃參數也都在 Area 上。
2. **專案資訊的舊參數不再讀取，也不退回讀它**。退回會讓沒填的區劃靜靜借用別人的類組，方向是放寬。
   舊專案改由面板的「填入所有未填的區劃」一次搬移，按「寫入模型」才寫入。
3. **同一區劃多塊 Area 類組不同時讀成 `混合（…）`**，不是讀不懂。這個值不是任何組別代碼，所以第 83 條的
   Ｈ－２組比較自然為假（各類組規定都要符合＝取最嚴），規則 DSL 不必擴充；第 79 條之 1 遇混合時，每一組都是
   該款所列組別才成立，有一組不在其列就不成立。
   部分 Area 未填則無法判讀。
4. **併入挑空的連通區劃另有欄位 `zone.connectedUseGroup`**，由各樓層連通區劃的 Area 以同一規則合併。
5. **不做主用途但書，也不檢查不同類組之間的一小時區劃**：依 106、113 年函，建造執照沒有這兩件事。
6. **區劃重新配置時沿用用途類組**：舊 Area 刪除前是使用者填寫值的唯一紀錄。各 Area 一致才沿用，混合的
   區劃列為請補填。

## 後果

- 規則集升為 `2026.11-provisional`，既有 stored run 都變成「需更新」。
- `防火檢討_用途類組` 綁在面積上成為必要參數；未綁的專案前置檢查會阻擋，要先執行「防火檢討參數設定」。
- MCP 的 `project.buildingUse` 停用，改用 `zones[].useGroup`。
- 將來實作第 86 條（B-3 組總樓地板面積 300 m²）或第 88 條（供該用途之專用樓地板面積合計）時，可以從各 Area
  的類組加總面積；整棟一個值做不到。
