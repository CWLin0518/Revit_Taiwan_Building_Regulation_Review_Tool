# 任務 3 影響審查：區劃編輯器用途

審查日期：2026-10-06。送審基線 014bdf0；工作目錄已有其他 agent 的用途與法規依據變更。本文件審查提案及既有下游，沒有修改程式，沒有執行 build 或 Revit 實測。

## 結論

支持以既有區劃面與 Area 參數表示用途，不新增垂直開口物件。下游讀值及法規判斷可沿用；但 3.2 的 mixed 回成空白、3.3 的用途變更預覽「不變」、3.4 的只在建立／更新 Area 時寫入，三者合起來有資料遺失及漏寫風險，應先修正再接受。用途不是免除成立的宣告。

## 1. Area 真值回讀與契約

可從 Area 的 `防火檢討_區劃用途` 回讀。`RevitWrittenZoneReader` 的 signature-only 約束針對工具產生的名稱／顏色；保留這兩者既有解析，另讀使用者參數，並將註解限定清楚即可。`RevitStoreyZoneReader` 已從 Area 參數讀用途，因此兩來源寫同一參數不需兩套讀取規則。

不能直接套用 Agreed 的「不一致視為未填」作為可寫回草稿：檢討缺口可以如此表示，編輯器卻可能把它清除。草稿須區分一致值、混合／未變更、顯式清除。警告不是資料保護。未做用途操作時，混合值應逐 Area 保留；使用者顯式選用途才整區覆寫。參數不存在、讀取失敗也不能假裝讀到空白。

## 2. Signature 與用途單獨變更

維持 `PlannedElementSignature.ForArea` 的 `name|hex|point` 可以，避免破壞從右解析與舊資料相容性。但不接受以狀態列說明來容忍用途變更仍報「不變」。

關鍵不是文案：`RevitZoneWriteBack.Apply` 的 `plan.IsEmpty` 分支只執行 `VerifyAreas` 然後返回；正常路徑只對 Areas stage 的 steps 執行 Area 寫入，`UnchangedAreas` 只有驗證。因此僅在 SetName 附近寫用途，會漏掉用途-only 更新。

建議獨立 Area 參數差異／操作計畫，含現值、目標值、操作意圖與目標 Area；納入預覽、IsEmpty、交易執行、失敗策略及結果摘要。可顯示「幾何不變，用途更新」及更新數量。Domain `ZoneDraft.Signature` 則須包含用途和混合／操作狀態，支援 Undo、Redo、dirty；所有 With*、Including、Excluding、ZoneDraftSet 複製路徑均須保留。新 Area 也必須進用途寫入計畫。

## 3. 空白語意

單一字串的空白不能同時代表一般區劃、維持原值及清除。建議編輯器提供明確「清除用途（一般區劃）」操作，未操作表示保留，混合顯示「多種用途」；確認視窗列出哪些 Area 將清除。批次面板既有空白＝不变更可以保留，但兩處須明示操作語意。若採空白直接清除，至少仍需獨立 mixed/unchanged 意圖，不能讓回讀缺口觸發清除。

## 4. 下游是否需要修改

- 批次設定面板：既有用途清單与逐列／批次寫入可沿用，不需新增欄；開著的面板若持有舊快照，編輯器寫入後須重新載入或提示刷新，避免舊資料覆寫。
- 檢討面板／判斷：`ReviewInputSources` 的 zone.use、`FireReviewModel`、`ReviewParameterSnapshot.ZoneInput` 已讀同一輸入，垂直區劃與第79條之1 分類可沿用。設定挑空後仍需既有避難層通達、樓層序與裝修等事實，不能自動補是或判為免除。
- `RevitStoreyZoneReader`／`AtriumStackResolver`：按同 Area Scheme、ownership package/zone、Level 及 Area 真值推得。兩寫入入口本身不影響算法；仍須每個開洞樓層有挑空 Area，不是一次設定跨樓層。Agreed 不一致回 null 是既有檢討限制，不應用編輯器靜默統一來掩蓋。
- `MergedAtriums.Of`：只有區劃清楚、用途挑空且第3項免除已成立才加入 merged。IsInterior 另檢查幾何關係、其他垂直區劃及 unreadable；單選挑空不會讓所有區劃線失效。編輯器的分割線仍是空間分析線，與法規邊界角色不同。用途視窗應說明「挑空與連通區劃間的線，僅在第3項免除成立後由檢討判斷為內部線」，不自動刪線或改模型。
- 失效／基線：`ReviewBaselineBuilder` 對 zone 附加各 context 的 ForZone inputs，用途已被涵蓋。實際改用途應讓相關舊結果／人工覆核需重新確認，這是正確失效；同值不得重寫。不須將用途再加入 ownership signature。跨樓層挑空會影響其他樓層推導，須實測其他工作包重開檢討能辨識此變化，不能只驗證當前包的 dirty 標記。

因此「面板與判斷不必修改」可作核心算法結論，但不能省略刷新、失效與多樓層驗收。

## 5. 寫入時機與交易

在既有 write-back TransactionGroup 內執行用途參數操作，讓幾何與用途同一 Undo、同一回滾策略。不要直接呼叫會自行開交易的批次 writer 造成獨立提交。可抽取不開交易的參數驗證／設定 helper 共用，避免复制参数解析規則。

預先檢查綁定、StorageType、唯讀及 Set 的結果。缺參數時訊息可沿提案，但必須有用途未寫入／部分完成狀態，不能顯示用途已套用。RollBackEverything 應把此失敗計入 FailureCount；其他策略明列失敗 Area。只改用途也必須開交易。回讀後若批次面板又改值，套用前重新取現值；未變更意圖保留最新值，顯式修改遇到舊基準衝突則提示再確認。

## 6. 其他影響與驗收

第164條是獨立道路陰影檢討：`Article164Command` 讀牆／樓板、道路與陰影設定，產生專用視圖／圖說；本次用途欄沒有改它的輸入或幾何，無須跟著新增用途判斷。防火側的裝修事實仍須依既有牆／天花板 Type 彙總；不可把區劃用途寫到 Type。MergedAtriums 的直接影響是既有 FireResistanceCheck、OpeningProtectionCheck 及 FireReviewRunner 的邊界／法源鏈。

色彩計畫、Area 名稱標註、Drafting View 單線圖保持既有幾何／名稱／顏色行為；用途欄不應隱含改名改色。若未設計用途圖例，不必擴充 Legend。用途更新後舊檢討視圖標示不能冒充新結果，須循既有重新檢討／標示更新流程；不直接以用途塗紅。

必要驗收：

1. 單改用途、幾何全不變：預覽有差異，套用成功，重開相同，Undo 整批復原。
2. 批次面板寫管道間，重開編輯器不操作用途直接套用：值保留。
3. 同區劃兩 Area 用途不同：顯示混合、未操作保留；顯式選用途整區統一；顯式清除才清除。
4. 新 Area、幾何拆分／合併、刪除復原及草稿所有複製路徑，檢查用途保留和目標 Area 正確。
5. 缺綁定、唯讀、型別不符、Set 失敗：摘要明示失敗；整批回滾策略無半套資料。
6. 挑空第3項成立／不成立／資料不足，普通鄰區／管道間鄰區，回歸 MergedAtriums、面積及第164條。
7. 多樓層用途改變、同值套用、開著的批次／檢討面板刷新，回歸 stale 與證據基線。

本次為靜態設計審查，尚未驗證上述新行為；Revit/WPF 既有無測試覆蓋，需實作後執行 build、Core tests 與 Revit 手動驗收。不要把基線測試通過當成本功能通過。
